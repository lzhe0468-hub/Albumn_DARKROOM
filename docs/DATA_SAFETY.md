# 照片库与数据保护

### 正式整理前的数据保护（2026-10-18）

程序资源与照片库分开保存。已实测：上一版写入照片、评分、逐张感想、信笺和日历记录，退出后替换程序资源，
本版重新读取时，各主存档与原图的 SHA-256 均保持一致。该测试验证了这次升级，不代表任何未来改动都可以跳过兼容性验证。

- 默认照片库也明确登记位置和照片库 ID；原库不可用或被替换时停止保存，避免无提示地新建空库。
- 存档版本或照片感想格式不受当前程序支持时，停止读取和覆盖；不把新格式误当损坏数据退回旧备份。
- 每次代码更新后第一次保存前，自动在 `.upgrade-backups/<代码标识>/` 保留本次更新前的 JSON 存档、上一版本 `.bak` 和校验清单，普通自动保存不覆盖这份副本。
- 这些升级副本只保护记录，原图仍在 `photos/`。它们与照片库在同一位置，不能替代整库的独立备份。
- 新的照片库位置不能设在程序安装目录中。打包采用代码与资源白名单，排除用户照片、存档和测试数据。
- 心愿页导入绑定最初选择的胶卷与位置，读取途中切换胶卷不会写错位置；未完成导入时阻止直接退出。

建议开始使用的顺序：

1. 退出旧窗口，打开当前 `dist/win-unpacked/DARKROOM.exe`。
2. 在首页“照片库位置”中选择独立于项目和程序目录的保存位置，例如选择 `D:\摄影资料`，自动创建其中的 `DARKROOM照片库`。
3. 先收录一小批照片、填写感想和评分，退出重开确认。
4. 退出软件，把**整个照片库文件夹**复制到另一个硬盘或移动硬盘，保留相机原片。备份包含标记文件、`photos/`、各 JSON、`.bak` 和隐藏的升级副本；只复制照片不能恢复评分与文字。
5. 以后每次更新前也做一次完整副本，再更新程序。恢复时先把备份复制成新的工作副本，再用“打开已有照片库”定位它，保留备份本身。

一键完整备份/恢复、回收站、更多图片格式和大量原图的性能优化仍未完成。
在更早且未包含这些保护的程序上回退使用前，也应先复制整库，避免旧代码直接编辑当前工作库。
`tests/storage-safety.cjs` 覆盖格式保护、升级副本、磁盘写入失败和默认库不可用等情况；
`tests/safety-runtime.cjs` 使用隔离数据验证真实更新、整库恢复和延迟导入。所有测试均不写入正式照片库。


## 照片库位置

首页右上角的“照片库位置”提供三个操作：

- **更改保存位置**：选择父文件夹，程序新建 `DARKROOM照片库`，复制所有照片、存档及备份，逐文件进行 SHA-256 校验后才切换。原照片库保留；已有同名目标目录不会被覆盖。
- **打开已有照片库**：选择含 `.darkroom-library.json` 标记的完整照片库文件夹，切换到该库。适用于手工复制整个照片库后重新定位，或使用先前保留的库。
- **在文件夹中查看**：打开当前照片库，可在退出软件后复制整个文件夹进行备份。

当前位置记录在应用用户数据目录中的 `library-location.json`。重启和更新程序会继续使用所选位置。
外置磁盘断开或位置设置损坏时，程序提示照片库不可用并阻止保存，不会在原位置自动新建空库。
照片库迁移过程中请保持软件开启；复制失败时原库仍保留，未完成的复制目录以 `.DARKROOM-importing-` 开头。
同时使用多个手工副本时，它们各自保存自己的修改；切换照片库不会合并内容。

`node tests/library-manager.cjs` 验证迁移、校验失败、原件保留、防覆盖、防嵌套、磁盘不可用与位置设置损坏。
`tests/library-runtime.cjs` 验证首页入口、目录选择 IPC、所有记录迁移、取消选择、重新定位和进程重启。

## 存储方式

胶卷保存在 album.json，摄影纪事、心愿信笺、日历和昵称分别保存在 journal.json、wishlist.json、calendar.json、people.json。各自的 .bak 保存上一版本；photos/ 保存导入的原图。存档与原图通过文件名关联，移动时必须复制整个照片库。

主存档损坏时尝试读取上一版本并提示；无法读取或不支持的格式会停止编辑和覆盖。保存失败时显示错误，文字页面保留输入以便重试。删除照片条目暂不清理内部原图，避免误删；这不等同于回收站。

未曾写入磁盘且已经丢失的早期页面内容无法恢复。
