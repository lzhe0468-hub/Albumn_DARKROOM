# 测试说明

所有运行测试使用 `tests/` 下的隔离照片库，不操作正式照片库。`npm run test:runtime` 每次生成新的 `.run-*` 目录，测试报告和截图不提交到 Git。

## 存储与元数据

运行 `npm test`，依次检查：

- 原图文件化、相册重读、评分、备份恢复、损坏数据保留与写入失败。
- 中文、多行与空文字，文档类型和路径校验。
- 照片库迁移、逐文件校验、防覆盖、磁盘不可用及位置设置损坏。
- EXIF 字段格式化、异常文件和手动编辑保护。
- 未知存档版本拒绝覆盖，更新快照校验与不可变性，模拟磁盘写入失败。

## 实际页面与重启

运行 `npm run test:runtime` 验证源码；完成 `npm run dist` 后，运行 `npm run test:runtime -- --packaged-test` 验证打包资源。

每组测试分别启动写入、读取两个进程，覆盖胶卷、照片、评分、文字自动保存与手动保存、失败重试、双人昵称与信笺、照片库迁移、独立灵感本和 2035 年日历边界。

如需用自己的 Nikon 原图重测 EXIF，在当前终端为 `DARKROOM_TEST_PHOTO` 环境变量设置原图的绝对路径，再运行上述命令。原图只用于本机测试，不提交到 Git 或打进应用。

## 更新与恢复

`tests/safety-runtime.cjs` 提供 `before`、`after` 两个阶段。先把待升级的 `app.asar` 复制到 `tests/.safety-runtime/before-update.asar`，用 Electron 测试入口运行 `before`；再构建新版本并运行 `after`。

测试保存各页面记录，对比主存档及原图 SHA-256，检查更新快照，验证心愿页延迟导入不会写错胶卷，并从完整库备份的工作副本重新打开记录。前后阶段必须配对运行，不能把已经修改过的旧样本当作新一轮基准。

`npm run check:release` 检查打包文件白名单、版本号、源码与资源包一致性，排除照片、测试数据、本地权限配置和存档。运行包与个人照片库始终分开管理。
